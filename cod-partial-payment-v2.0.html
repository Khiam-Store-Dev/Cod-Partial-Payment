ℹ️ About — دفع جزئي COD
📋 وصف الأداة

الهدف: تسجيل دفعة جزئية (أقل من إجمالي قيمة الأوردر) على أوردر COD، بتسجيلها مباشرة كـ transaction على شوبيفاي، مع توثيق طريقة الدفع وملحوظة على الأوردر.

المستخدمون المستهدفون: موظفو التحصيل / الكاشير.

كيف تعمل — Workflow (معالج 3 خطوات)

  1. تسجيل الدخول بالـ PIN.
  2. الخطوة 1: إدخال رقم الأوردر والضغط على "بحث" — الأداة تستعلم من شوبيفاي وتعرض Current Subtotal / Shipping / Current Total.
  3. الخطوة 2: إدخال المبلغ المستلم فعلياً — المبلغ المتبقي المتوقع يُحسب تلقائياً للعرض فقط (لا يُرسل لشوبيفاي).
  4. الخطوة 3: اختيار طريقة الدفع من القائمة (مصدرها ميتافيلد custom.cod_partial_payment_method) ثم الضغط على "تسجيل الدفع".
  5. عند التأكيد: تسجيل الدفعة كـ transaction بقيمة المبلغ + تحديث الميتافيلد بطريقة الدفع + إضافة ملحوظة على الأوردر.
  6. مراجعة كل العمليات السابقة من تاب "سجل العمليات".

FEATURE MAP

  • §AUTH — Universal D1 Auth (check_employee / register_pin / verify_employee / log_logout / get_employees)
  • §PAYMENT — findOrderByNumber() (بحث بالـ GraphQL + رصيد Current Subtotal/Shipping/Current Total/note) + getPaymentMethodChoices() (قراءة choices الميتافيلد) + setPaymentMethodMetafield() (metafieldsSet) + appendOrderNote() (orderUpdate) + recordPartialTransaction() (REST transactions.json) + endpoints lookup_order / get_payment_methods / record_payment
  • §LOG-ENDPOINTS — get_logs / get_logs_count / get_logs_export
  • §TOOL-JS::wizard — lookupOrder() (خطوة 1) → goToWizardStep() (تنقل) → updateRemainingPreview() (خطوة 2، عرض فقط) → renderPaymentMethodOptions() / selectPaymentMethod() (خطوة 3) → submitPayment()

KEY VARIABLES

  • currentEmployee — { username, displayName } في الذاكرة فقط (لا localStorage)
  • LS_URL = 'cod_partial_payment_worker_url' · LS_SECRET = 'cod_partial_payment_worker_secret'
  • TOOL_NAME = 'cod_partial_payment' — قيمة tool في جدول logs
  • currentOrderData — نتيجة lookup_order (orderId / orderName / currentSubtotal / shipping / currentTotal) — في الذاكرة فقط، تُمسح بعد كل عملية أو تسجيل خروج
  • paymentMethodsList — كاش لقائمة طرق الدفع من get_payment_methods، يُحمَّل بعد تسجيل الدخول
  • selectedPaymentMethod · wizardStep (1/2/3) — حالة المعالج في الذاكرة

NOTES

  • الدفع دايماً عبر REST orders/{id}/transactions.json — ممنوع استخدام orderCapture mutation (لا تعمل مع COD).
  • البحث عن الأوردر بالاسم عبر name:#... filter، والرد يشمل دايماً الـ orderId الرقمي عشان الهايبر لينك لشوبيفاي.
  • Current Subtotal / Current Total تُقرأ من currentSubtotalPriceSet / currentTotalPriceSet — مش subtotalPriceSet/totalPriceSet (تلوث بعد أي مرتجع).
  • طريقة الدفع تُقرأ حياً من الـ choices الموجودة على تعريف ميتافيلد custom.cod_partial_payment_method — تعديل القائمة في شوبيفاي أدمن ينعكس فوراً بدون تعديل الكود.
  • order.note ليس له mutation "إضافة" — الـ Worker بيجيب النص الحالي طازة في نفس الطلب ويلحق السطر الجديد قبل الكتابة بـ orderUpdate.
  • لو فشل تحديث الميتافيلد أو الملحوظة بعد نجاح الدفع، العملية تُعتبر ناجحة (الفلوس اتسجلت فعلاً) وبيُعرض تحذير warnings للموظف بدل التراجع عن الدفع.
  • الأداة أصلها من EcomModa (نفس الوظيفة بالظبط) — الفرق هنا بس معايير الـ UI/D1/CORS الخاصة بخيام.
